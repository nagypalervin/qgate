# 2026-11-08: project skeleton and workflow

**Went well:** From idea to a building Rust workspace with CI in one
session. Writing CLAUDE.md and ADR 0001 up front forced decisions (Rust,
deltas not scores, deterministic core) before any real code existed.

**Had to step in:** The first plan for the spec workflow had no place for
progress or decisions made during implementation; a spec only described
the intent. Caught by the human, not the AI. Also, closing a spec after
merge would have needed an extra docs-only PR; moved closing into the last
PR instead.

**Surprise:** A local test caught a real bug in the skeleton itself
(`Display` ignored padding, so columns did not line up).

**Decisions:** Evaluated BMAD (too much ceremony for a solo project), then a
home-grown spec flow, then existing spec-driven tools. Chose **OpenSpec**
(propose / apply / archive, living specs, few files), plus our own
independent reviewer agent and this journal.

**Effort:** one evening, mostly discussion.

**Blog idea:** "Your AI pair will happily build a process that forgets what
happened."

**Name:** `qgate` (quality gate) says what the tool does in CI and is
instantly understood.
